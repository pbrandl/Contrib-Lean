# Sicherheits-Update für den Abend der Bietrunde (16.10.2026)

## Was sich ändert

- **Sperren gelten pro Handy, nicht mehr pro WLAN.** Wer sich vertippt, sperrt nur sein eigenes Handy für dieses Konto: nach 5 Fehlversuchen 1 Minute, danach doppelt so lang, bis höchstens 1 Stunde. Alle anderen im selben WLAN kommen weiter rein, auch der Admin.
  Getestet mit 600 Mitgliedern hinter einer einzigen IP-Adresse und 336 Tippfehlern: alle 600 kamen rein. Mit der alten Version kamen im selben Test nur 86 rein.
- **PIN-Raten bleibt begrenzt, und niemand von außen kann den Saal aussperren.**
  - Pro Konto und Netzwerk sind höchstens 20 Fehlversuche von fremden Geräten möglich, danach einer alle 18 Minuten. Beim Admin sind es 10, danach einer alle 2 Stunden. Ein Angreifer von außerhalb verbraucht damit nur das Kontingent seines eigenen Netzwerks, nie das des Saal-WLANs.
  - Gegen Angreifer, die viele Adressen durchwechseln, gibt es zusätzlich eine Obergrenze pro Konto: 100 Fehlversuche, danach 100 pro Tag (beim Admin 30, danach einer pro Stunde). Diese Grenze gilt nicht für das Netzwerk, in dem sich der Admin zuletzt angemeldet hat, also für das Saal-WLAN.
  - Geräte, auf denen sich das Mitglied schon einmal richtig angemeldet hat, sind von beiden Grenzen ausgenommen.
- **Neue Mitglieder, die du einzeln einträgst, bekommen eine zufällige Start-PIN.** Sie wird dir nach dem Eintragen einmal angezeigt. Beim Import bleibt es bei der PIN aus der Datei oder 1234.
- **Das Protokoll (`audit.log`) zeigt bei jedem Gebot, von welcher Adresse, welchem Browser und welchem Gerät es kam.** Anmeldungen und Fehlversuche stehen auch drin. PINs stehen nie drin.
- Weitere Schutzmaßnahmen:
  - Sicherheits-Header gegen das Einbetten der Seite in fremde Seiten und eingeschleusten Code.
  - Größenlimits für Anfragen.
  - Ein Schreib-Limit pro Mitglied gegen Skripte.
  - Stündliche Sicherungen während des Abends.
  - Aktualisierte Express-Version: `npm audit` meldet keine Lücken mehr.
- **Wenn der Server nicht antwortet, hängt die Seite nicht mehr.** Ein Gebot ohne Antwort wird automatisch noch einmal gesendet, und der Server zählt es trotzdem nur einmal. So geht kein Klick verloren und keiner wird doppelt gezählt.

## Einspielen auf dem Uberspace

Den Ordner `data/` mit Datenbank, Protokoll und Sicherungen fasst das Update nicht an.

1. **Alles sichern**, auch die Daten:

   ```bash
   cp -a ~/fundraiser-app ~/fundraiser-app-vorher-$(date +%F)
   ```

2. **Node-Version prüfen.** Mindestens 18 ist nötig:

   ```bash
   node --version
   ```

3. **Das Zip hochladen und den Code übernehmen:**

   ```bash
   unzip -o fundraiser-app-sicherheit.zip -d ~/update
   rsync -a --exclude node_modules --exclude backend/data ~/update/fundraiser-app/ ~/fundraiser-app/
   ```

4. **Backend aktualisieren.** Das installiert Express 4.22.3 und startet den Dienst neu:

   ```bash
   cd ~/fundraiser-app/backend && npm ci && supervisorctl restart fundraiser
   ```

   Angemeldete Mitglieder bleiben angemeldet. Alle Sperren und Zähler beginnen wieder bei null.

5. **Frontend bauen und veröffentlichen.** Die Datei `frontend/.env` muss mit dabei sein, sie ist im Zip enthalten:

   ```bash
   cd ~/fundraiser-app/frontend && npm run build && rsync -a --delete build/ ~/html/
   ```

6. **Prüfen:**

   ```bash
   curl -sI https://franz.uber.space/ | grep -iE 'content-security|x-frame|nosniff|referrer|permissions'
   curl -s https://franz.uber.space/api/health
   ```

   In der Ausgabe des ersten Befehls müssen diese fünf Header vorkommen: `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` und `Permissions-Policy`. Doppelte Zeilen sind in Ordnung, die kann Uberspace zusätzlich setzen. Fehlen sie ganz, ist `mod_headers` nicht aktiv; dann bitte melden. Danach die Seite einmal auf dem Handy öffnen und anmelden.

7. **Optional, die Tests auf dem Server**, gegen eine leere Test-Datenbank:

   ```bash
   cd ~/fundraiser-app/backend && node test.js /nonexistent
   ```

**Zurück zur alten Version**, falls nötig:

```bash
supervisorctl stop fundraiser
rsync -a --delete ~/fundraiser-app-vorher-DATUM/ ~/fundraiser-app/
cd ~/fundraiser-app/frontend && npm run build && rsync -a --delete build/ ~/html/
supervisorctl start fundraiser
```

## Vor dem Abend

- **Melde dich als Admin einmal auf dem Gerät an, das du am Abend benutzt.** Dann gilt es als vertrauenswürdig, und du kommst auch rein, wenn jemand die Admin-PIN zu erraten versucht.
- **Melde dich am Abend gleich zu Beginn im Saal-WLAN als Admin an.** Damit ist das Saal-WLAN 24 Stunden lang von der Obergrenze pro Konto ausgenommen.
- **Lade eine Admin-Seite, die schon vor dem Update offen war, einmal neu.** Eine alte Seite vergibt beim Eintragen weiter die Start-PIN 1234 und zeigt das auch so an.
- **Wähle für den Admin eine 6-stellige PIN.** Das macht das Raten hundertmal schwerer, ohne dass sich sonst etwas ändert.
- **Mitglieder mit der Start-PIN 1234** (aus einem Import oder von früher) sollten nach dem ersten Anmelden eine eigene PIN wählen. Die App erinnert sie daran.
- **Wenn jemand „Zu viele Fehlversuche“ sieht:** kurz warten, oder du setzt im Admin-Bereich mit „PIN setzen“ eine neue PIN. Das hebt alle Sperren für dieses Konto sofort auf.
